2. Cómo se conectan las secciones

Toda la página es un solo archivo de ensamblaje. No hay rutas, no hay navegación entre páginas: hay una lista ordenada de componentes y un conjunto de anclas (id) para saltar entre ellos.

2.1 El orden final de la página

app/page.tsx ├── Header (fijo, fuera de <main>) └── main ├── Hero #inicio foto + nombres + fecha ├── Bienvenida #bienvenida mensaje de los novios ← Fase 11 ├── NuestraHistoria #historia texto + carrusel ← Fase 14 ├── CuentaRegresiva #countdown sección café + contador ├── ElGranDia #gran-dia lugar, horarios, mapa ├── Cronograma #cronograma línea de tiempo ← Fase 12 ├── CodigoVestimenta #vestimenta 2 cards con foto ← Fase 13 ├── Hospedaje #hospedaje hoteles o "muy pronto" ├── Galeria #galeria collage + lightbox ← Fase 15 ├── PreguntasFrecuentes #faq acordeón ├── Rsvp #rsvp formulario + Oracle ← Fase 18 ├── Despedida #despedida agradecimiento ← Fase 16 └── Footer (sin ancla) cierre oscuro ← Fase 17

2.2 Las tres capas de cada sección

Entender esto es lo que hace que el proyecto escale sin desorden. Cada sección tiene siempre las mismas tres capas:

Si un texto cambia, se toca la capa 1. Si un color cambia, la capa 2. Si cambia el orden de la página, la capa 3. Nunca se mezclan.

4. Conceptos de Next.js que vas a aprender

4.1 Server Components y Client Components

En el App Router, un componente es de servidor por defecto: se ejecuta en el servidor, puede leer la base de datos y no envía JavaScript al navegador. Es ideal para texto y fotos.

Un componente se vuelve de cliente cuando se marca con "use client" en la primera línea. Solo entonces puede usar:

  • estado (useState) y efectos (useEffect),
  • eventos del usuario (onClick, onChange, onMouseEnter),
  • APIs del navegador (window, document, matchMedia).
La regla no es "usar cliente para todo". Cada componente cliente suma JavaScript que el invitado descarga, posiblemente con datos móviles. Por eso solo el carrusel, el lightbox y el formulario serán cliente; el resto queda en servidor.

4.2 Hidratación, y por qué importa

El servidor manda HTML ya armado. Después, React lo "hidrata": le adjunta los eventos y lo vuelve interactivo. Si el HTML del servidor y el primer render del cliente no coinciden, React avisa con un error de hidratación.

Por eso el contador muestra -- al principio: en el servidor no existe Date.now() del visitante. La misma lógica aplica al carrusel: la foto activa inicial siempre es la 0, y el setInterval arranca después, dentro de un useEffect.

4.3 Los hooks que vas a usar

HookQué haceDónde se usa
useStateGuarda un valor que, al cambiar, redibuja el componenteFoto activa, modal abierto, pausa
useEffectEjecuta código después del render y devuelve una limpiezaIntervalos, listeners, matchMedia
useRefGuarda una referencia a un elemento del DOM sin redibujarEl <dialog> del lightbox
useCallbackMemoriza una función para que no cambie en cada renderLa función "siguiente" del carrusel
useActionStateConecta un formulario a una server action y expone estado y pendienteFormulario RSVP

4.4 Server Actions

Una server action es una función que se ejecuta en el servidor pero se llama desde el navegador como si fuera local. Es la forma moderna de procesar un formulario sin escribir un endpoint a mano.

// 1. Se declara en un archivo con "use server" arriba
"use server";
export async function guardarRsvp(prev, formData) { /* ... */ }

// 2. Se pasa al formulario
<form action={formAction}> ... </form>

Next se encarga del transporte, de la serialización y de la protección CSRF. Tú solo escribes la lógica.

4.5 Variables de entorno

Las credenciales de Oracle nunca van en el código ni en un componente. Van en .env.local (que no se sube a Git) y se leen con process.env solo en el servidor.

PrefijoVisible enUso
ORACLE_USERSolo servidorUsuario de la base
NEXT_PUBLIC_APP_URLServidor y navegadorDatos que pueden ser públicos
Todo lo que empiece con NEXT_PUBLIC_ se incrusta en el JavaScript del navegador. Si le pones ese prefijo a una contraseña, cualquiera la lee con F12. La contraseña de Oracle va sin prefijo.

4.6 next/image con y sin fill

ModoCuándoRequisito
width + heightÍconos y logosValores fijos; la proporción se conserva

Con fill siempre se acompaña object-cover (recorta sin deformar) y sizes (le dice al navegador cuánto espacio ocupa la imagen en cada breakpoint).

Qué significa cada atributo del SVG

AtributoQué hace
viewBox="0 0 1000 120"Define un sistema de coordenadas interno de 1000 × 120
preserveAspectRatio="none"Estira el dibujo al contenedor, sin mantener proporción
d="M0,60 C..."La ruta: M mueve el lápiz, C dibuja una curva de Bézier, S continúa suavemente

El móvil no usa la onda. A 375 px de ancho, seis puntos en una onda quedan ilegibles. En móvil se muestra una línea vertical a la izquierda con los hitos apilados; la onda aparece desde md.

8. Fase 14 — Carrusel de Historia (a fondo)

Es el primer componente realmente interactivo del sitio. Vale la pena entenderlo bien porque el mismo patrón se repite en cualquier carrusel que hagas después.

8.1 La idea en una frase

Todas las fotos están montadas al mismo tiempo, una encima de otra; solo cambia la opacidad de la activa. No hay desplazamiento, no hay posición, no hay transformaciones: solo opacity. Eso es lo que produce el fundido.

Contenedor (alto fijo, overflow-hidden) ┌─────────────────────────────────────┐ │ figura 0 opacity-0 (invisible) │ │ figura 1 opacity-100 (visible) │ ← todas están, apiladas │ figura 2 opacity-0 (invisible) │ │ figura 3 opacity-0 (invisible) │ └─────────────────────────────────────┘ ▲ cambia el índice cada 6 s └── clase opacity-0 / opacity-100 + transition-opacity

8.2 Ventajas frente al carrusel deslizante

AspectoFundido (elegido)Deslizante
JS necesarioUn índice y un intervaloÍndice, offset, gestos táctiles
Salto de layoutNinguno: el contenedor tiene alto fijoFrecuente si no se calcula el ancho
AccesibilidadSimple: se ocultan las inactivasHay que gestionar foco y scroll
EstéticaElegante, editorialMás "app"

8.4 El componente completo, explicado

"use client";

import Image from "next/image";
import { useCallback, useEffect, useState } from "react";
import type { HistoryPhoto } from "@/data/wedding-data";

type Props = { photos: HistoryPhoto[]; intervalo?: number };

export default function HistoriaCarrusel({ photos, intervalo = 6000 }: Props) {
    const [activa, setActiva] = useState(0);
    const [pausado, setPausado] = useState(false);
    const [reducir, setReducir] = useState(false);

    /* Avanza circularmente: 0,1,2,3,0,1... */
    const siguiente = useCallback(() => {
        setActiva((i) => (i + 1) % photos.length);
    }, [photos.length]);

    /* Respeta la preferencia del sistema: sin animaciones automáticas */
    useEffect(() => {
        const mq = window.matchMedia("(prefers-reduced-motion: reduce)");
        setReducir(mq.matches);
        const onChange = (e: MediaQueryListEvent) => setReducir(e.matches);
        mq.addEventListener("change", onChange);
        return () => mq.removeEventListener("change", onChange);
    }, []);

    /* El reloj: se reinicia si se pausa y se limpia al desmontar */
    useEffect(() => {
        if (pausado || reducir || photos.length <= 1) return;
        const id = setInterval(siguiente, intervalo);
        return () => clearInterval(id);
    }, [pausado, reducir, intervalo, siguiente, photos.length]);

    return (
        <div className="relative"
             onMouseEnter={() => setPausado(true)}
             onMouseLeave={() => setPausado(false)}
             onFocus={() => setPausado(true)}
             onBlur={() => setPausado(false)}>

            <div className="relative h-80 w-full overflow-hidden rounded-2xl md:h-[400px]">
                {photos.map((photo, i) => (
                    <figure key={photo.src}
                            aria-hidden={i !== activa}
                            className={`absolute inset-0 transition-opacity duration-1000 ${
                                i === activa ? "opacity-100" : "opacity-0"
                            }`}>
                        <Image src={photo.src} alt={photo.alt} fill
                               sizes="(min-width: 768px) 50vw, 100vw"
                               className="object-cover" />

                        <div className="absolute inset-0 bg-linear-to-t from-ink/75 via-transparent to-transparent" />

                        <figcaption className="absolute inset-x-0 bottom-0 p-5 font-sans text-sm text-cream">
                            {photo.caption}
                        </figcaption>
                    </figure>
                ))}
            </div>

            <div className="mt-5 flex justify-center gap-2">
                {photos.map((photo, i) => (
                    <button key={photo.src} type="button"
                            onClick={() => setActiva(i)}
                            aria-label={`Ver foto ${i + 1} de ${photos.length}`}
                            aria-current={i === activa ? "true" : undefined}
                            className={`h-2 rounded-full transition-all duration-300 ${
                                i === activa ? "w-6 bg-terracotta" : "w-2 bg-sand"
                            }`} />
                ))}
            </div>
        </div>
    );
}

8.5 Por qué cada decisión

DetalleRazón
absolute inset-0 en cada figuraApila todas en el mismo lugar; sin esto se verían una debajo de otra
Alto en el contenedor (h-80 md:h-[400px])Con fill la imagen necesita un padre con altura; además evita el salto de layout
aria-hidden en las inactivasUn lector de pantalla no debe leer cuatro descripciones a la vez
useCallback en siguienteSi la función cambiara en cada render, el useEffect reiniciaría el intervalo constantemente
return () => clearInterval(id)Sin la limpieza, al desmontar quedaría un reloj corriendo (fuga de memoria)
pausado y reducirNadie debe perder una foto porque el mouse pasó por encima, ni sufrir animaciones si pidió reducirlas
(i + 1) % lengthEl módulo hace circular el índice: después del último vuelve al primero
Puntos como <button>Son navegables con teclado; un div con onClick no lo es

PiezaQué hace

9.3 El lightbox con <dialog>

HTML ya tiene un elemento para esto: <dialog>. Con showModal() se abre encima de todo, bloquea el resto de la página y captura Escape automáticamente. No hay que reinventar el foco ni el fondo.

"use client";

import Image from "next/image";
import { useEffect, useRef } from "react";
import type { GalleryPhoto } from "@/data/wedding-data";

type Props = {
    photos: GalleryPhoto[];
    index: number | null;               // null = cerrado
    onClose: () => void;
    onNavigate: (i: number) => void;
};

export default function Lightbox({ photos, index, onClose, onNavigate }: Props) {
    const ref = useRef<HTMLDialogElement>(null);

    /* Abre y cierra el diálogo cuando cambia el índice */
    useEffect(() => {
        const dialog = ref.current;
        if (!dialog) return;

        if (index !== null && !dialog.open) {
            dialog.showModal();
            document.body.style.overflow = "hidden";
        }
        if (index === null && dialog.open) {
            dialog.close();
            document.body.style.overflow = "";
        }
    }, [index]);

    /* Flechas del teclado mientras está abierto */
    useEffect(() => {
        if (index === null) return;
        const onKey = (e: KeyboardEvent) => {
            if (e.key === "ArrowRight") onNavigate((index + 1) % photos.length);
            if (e.key === "ArrowLeft")  onNavigate((index - 1 + photos.length) % photos.length);
        };
        window.addEventListener("keydown", onKey);
        return () => window.removeEventListener("keydown", onKey);
    }, [index, photos.length, onNavigate]);

    /* Escape y clic en el fondo cierran */
    return (
        <dialog
            ref={ref}
            onClose={onClose}
            onClick={(e) => { if (e.target === e.currentTarget) onClose(); }}
            className="m-auto w-full max-w-5xl rounded-2xl bg-ink/95 p-0
                       backdrop:bg-ink/80 backdrop:backdrop-blur-sm">

            {index !== null && (
                <figure className="relative">
                    <div className="relative aspect-[3/2] w-full">
                        <Image src={photos[index].src} alt={photos[index].alt} fill
                               sizes="90vw" className="object-contain" />
                    </div>

                    <figcaption className="flex items-center justify-between gap-4 p-4 font-sans text-sm text-cream">
                        <span>{photos[index].caption ?? photos[index].alt}</span>
                        <button type="button" onClick={onClose}
                                className="rounded-full border border-cream/30 px-4 py-1
                                           text-xs uppercase tracking-[0.2em]">
                            Cerrar
                        </button>
                    </figcaption>
                </figure>
            )}
        </dialog>
    );
}

9.5 Accesibilidad de la galería

  • Cada foto es un <button>, no un div: se abre con teclado.
  • El botón lleva aria-label describiendo la foto ("Ampliar: Sonia y David en el jardín").
  • Al cerrar, el foco vuelve solo al botón que abrió (el navegador lo hace con dialog.close()).
  • Se bloquea el scroll del fondo mientras el modal está abierto.
  • Las flechas izquierda/derecha funcionan con el teclado.

12. Fase 18 — RSVP con Oracle (a fondo)

12.1 Qué es Autonomous Database "Always Free"

Oracle Autonomous Database es un servicio administrado: Oracle se encarga de parches, respaldos y ajuste. La capa Always Free es gratuita sin fecha de expiración e incluye 20 GB de almacenamiento y dos instancias. Se administra desde el navegador (Database Actions), así que no necesitas instalar nada para empezar.

Por qué encaja con este proyecto: el sitio se publica en Vercel, que no puede alojar un servidor Oracle. Una base en la nube resuelve eso y te deja practicar SQL real desde el primer día.

12.2 Arquitectura del flujo

Invitado │ llena el formulario y envía ▼ Rsvp.tsx ("use client") ← useActionState, estados de error y "enviando" │ │ form action ▼ actions/rsvp.ts ("use server") ← valida, arma los binds, ejecuta │ │ pool.execute(sql, binds) ▼ lib/oracle.ts ← un solo pool para toda la app │ │ TCPS 1522 (cifrado) ▼ Oracle Autonomous Database (Always Free) └── tabla RSVP

12.6 El pool de conexiones

// lib/oracle.ts
import oracledb from "oracledb";

declare global {
    var __oraclePool: oracledb.Pool | undefined;
}

export async function getPool() {
    if (!globalThis.__oraclePool) {
        globalThis.__oraclePool = await oracledb.createPool({
            user: process.env.ORACLE_USER,
            password: process.env.ORACLE_PASSWORD,
            connectString: process.env.ORACLE_CONNECT_STRING,
            poolMin: 1,
            poolMax: 4,
            poolTimeout: 60,
        });
    }
    return globalThis.__oraclePool;
}
DetallePor qué
Pool y no una conexión por requestAbrir una conexión cuesta cientos de milisegundos; el pool las reutiliza
globalThisEn desarrollo, Next recarga el módulo en cada cambio. Sin esto, cada recarga crearía un pool nuevo hasta agotar el límite de sesiones de Oracle
poolMax: 4Una boda no necesita más. El plan gratuito tiene un límite de sesiones y conviene no acercarse
import oracledbEl driver solo se ejecuta en el servidor. Nunca debe importarse desde un componente cliente

12.7 La server action

// app/actions/rsvp.ts
"use server";

import { getPool } from "@/lib/oracle";

export type RsvpState = { ok: boolean; message: string };

export async function guardarRsvp(
    _prev: RsvpState,
    formData: FormData,
): Promise<RsvpState> {
    const nombre = String(formData.get("nombre") ?? "").trim();
    const correo = String(formData.get("correo") ?? "").trim();
    const telefono = String(formData.get("telefono") ?? "").trim();
    const asiste = formData.get("asiste") === "no" ? "N" : "S";
    const acompanantes = Number(formData.get("acompanantes") ?? 0);
    const restricciones = String(formData.get("restricciones") ?? "").trim();
    const mensaje = String(formData.get("mensaje") ?? "").trim();

    if (nombre.length < 3) {
        return { ok: false, message: "Escribe tu nombre completo." };
    }
    if (!Number.isInteger(acompanantes) || acompanantes < 0 || acompanantes > 10) {
        return { ok: false, message: "El número de acompañantes no es válido." };
    }

    try {
        const pool = await getPool();
        await pool.execute(
            `INSERT INTO RSVP
                 (NOMBRE, CORREO, TELEFONO, ASISTE, ACOMPANANTES, RESTRICCIONES, MENSAJE)
             VALUES (:nombre, :correo, :telefono, :asiste, :acompanantes, :restricciones, :mensaje)`,
            { nombre, correo, telefono, asiste, acompanantes, restricciones, mensaje },
            { autoCommit: true },
        );
        return { ok: true, message: "¡Gracias! Tu confirmación quedó registrada." };
    } catch (error) {
        console.error("Error al guardar RSVP", error);
        return { ok: false, message: "No pudimos guardar tu confirmación. Intenta de nuevo." };
    }
}

12.8 Bind variables: la parte de seguridad

Nunca se concatena texto del usuario dentro del SQL. Se usan bind variables: el SQL lleva :nombre y los valores viajan aparte.

// ❌ Mal: inyección SQL. Con nombre = "x'); DROP TABLE RSVP; --" se borra la tabla
await pool.execute(`INSERT INTO RSVP (NOMBRE) VALUES ('${nombre}')`);

// ✅ Bien: el valor nunca se interpreta como SQL
await pool.execute("INSERT INTO RSVP (NOMBRE) VALUES (:nombre)", { nombre });

Además de la seguridad, los binds permiten que Oracle reutilice el plan de ejecución: es más rápido.

12.11 Despliegue en Vercel

  1. Project Settings → Environment Variables: cargar ORACLE_USER, ORACLE_PASSWORD y ORACLE_CONNECT_STRING.
  2. Nunca marcarlas como NEXT_PUBLIC_.

12.12 Privacidad y abuso

  • Pide solo lo necesario: nombre, asistencia, acompañantes y restricciones. El correo y el teléfono son opcionales.
  • No registres datos personales en console.log.
  • Un formulario público recibe spam. Cuando funcione, se puede agregar un campo trampa oculto y un límite por IP.
  • El dueño de los datos debe poder borrarlos: un DELETE por nombre es suficiente para una boda.
