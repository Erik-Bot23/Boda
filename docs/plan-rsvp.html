1. El panorama: dos proyectos, una base de datos

Esta fase son dos aplicaciones que se conectan a la misma base Oracle. No es un solo proyecto con dos partes: son dos carpetas, dos despliegues y dos dominios distintos.

PROYECTO 1 · la invitación (este repositorio) invitado → clic en "Confirmar" → modal RSVP │ ▼ Server Action (Next.js) ├─ valida y cuenta pases ├─ INSERT en INVITADOS └─ envía el correo (Resend) │ │ TCP sobre TLS (puerto 1522) ▼ ┌──────────────────────────────┐ │ Oracle Autonomous Database │ │ Always Free (20 GB) │ │ USUARIOS · INVITADOS · │ │ ACOMPANANTES │ └──────────────┬───────────────┘ │ │ mismo driver, mismo pool ▼ PROYECTO 2 · el dashboard (carpeta nueva) cliente → /login → Auth.js valida contra USUARIOS │ ▼ /dashboard (protegida) SELECT con JOIN, tabla y resumen

1.1 Por qué dos proyectos y no uno

MotivoDetalle
PermisosEl invitado no debe tener acceso al dashboard ni a las credenciales. Separados, no hay forma de equivocarse
SeguridadLa clave del dashboard no vive en el sitio público. Un error en el sitio de la boda no expone el panel
DespliegueCada uno se actualiza por separado. Una mejora en el dashboard no obliga a tocar la invitación
ReutilizaciónSi el desarrollador hace más bodas, el dashboard es el mismo y solo cambia el USUARIO_ID
Lo único que comparten es la base. Los dos proyectos instalan oracledb y tienen su propio lib/oracle.ts. Es el mismo archivo copiado, no un paquete compartido.

1.2 ¿Qué es exactamente "Autonomous Database Always Free"?

Oracle Cloud ofrece bases de datos administradas: Oracle aplica parches, respaldos y ajuste automáticamente. La capa Always Free es gratuita sin fecha de expiración e incluye 20 GB. Se maneja desde el navegador (Database Actions), así que no hay servidor que cuidar.

ConceptoQué significa
AutonomousEl motor se autogestiona: parches, respaldos, índices y rendimiento
Always FreeNivel gratuito permanente, con 20 GB y límites de CPU/OCPU bajos pero suficientes
ADBLa abreviatura del servicio (Autonomous Database)
Database ActionsUna consola web dentro del mismo servicio para ejecutar SQL sin instalar nada

2. Oracle Autonomous Database

2.1 Crear la instancia (una sola vez)

  1. Entra a oracle.cloud y crea la cuenta (pide tarjeta, pero el nivel Free no cobra).
  2. En Oracle Cloud Infrastructure, menú → Autonomous Database → Create.
  3. Tipo: Transaction Processing. Nombre y contraseña del usuario ADMIN (guárdala en un lugar seguro).
  4. Región: la más cercana a México (mx-queretaro o mx-monterrey si está disponible).
  5. Acceso: Allow secure access from anywhere (por ahora; se puede restringir después).

2.2 El driver: oracledb en modo thin

npm install oracledb

El driver de Oracle para Node.js tiene dos modos:

ModoCómo funcionaCuándo usarlo
ThinJavaScript puro. No instala nada del Oracle ClientSiempre aquí. Funciona en Vercel sin compilar nativos
ThickCarga la librería nativa del Oracle Client ( Instant Client )Solo si necesitas funciones avanzadas (Kerberos, PKIX, ...)
Thin es la clave del despliegue: Vercel compila funciones serverless en un entorno donde no puedes instalar librerías nativas. Como thin es JavaScript puro, la conexión funciona tal cual.

2.3 La cadena de conexión

En la consola de la base, Database connection → Connection strings copia la cadena TCPS (puerto 1522). Tiene esta forma:

(description=(retry_count=20)(retry_delay=3)
  (address=(protocol=tcps)(port=1522)(host=adb.mx-queretaro-1.oraclecloud.com))
  (connect_data=(service_name=g8f3a2c1b2e_miboda_high.adb.oraclecloud.com))
  (security=(ssl_server_dn_match=yes)))
ParteQué indica
protocol=tcpsTLS cifrado, igual que HTTPS pero en el puerto 1522
host=adb…oraclecloud.comLa puerta de entrada de tu base
service_name=g8f3a2c1b2e_miboda_highEl "nombre del servicio" dentro de la base. Viene en tres sabores: _high, _medium, _low
retry_count / retry_delaySi la base está ocupada, reintenta 20 veces esperando 3 segundos. Importante en el nivel Free, que se duerme
ssl_server_dn_match=yesVerifica que el certificado del servidor corresponda al servicio
Si el driver se queja del certificado (DPI-1049 o SSL handshake failed), hay dos caminos:
A) En Database Actions → Database connection → Wallet, descarga el wallet y apunta a la carpeta con walletLocation.
B) Para desarrollo, cambia ssl_server_dn_match=yes por no. Es menos estricto; para producción conviene el wallet.

2.4 El pool de conexiones

Abrir una conexión Oracle cuesta cientos de milisegundos. Un pool las abre una vez y las reutiliza. Por eso toda la aplicación comparte uno solo.

Sin globalThis el pool se multiplicaría. En desarrollo, Next recarga los módulos con cada cambio. Si el pool se creara dentro de la función, cada recarga abriría uno nuevo y llegarías al límite de sesiones del nivel Free.

Se crean una sola vez, desde Database Actions → SQL. Tres tablas: el cliente, sus invitados y (opcional) los acompañantes.

3.1 La contraseña nunca en texto plano

npm install bcryptjs
import bcrypt from "bcryptjs";

//Al crear el usuario
const hash = await bcrypt.hash("miContraseñaSegura", 12);

//Al iniciar sesión
const valida = await bcrypt.compare("laQueEscribieron", hashDeLaBase);

El número 12 es el "costo": cuántas vueltas de cifrado. 10–12 es el estándar. Cada vuelta hace el hash más lento de calcular para un atacante, sin afectar apenas al inicio de sesión.

3.2 Consulta de control

SELECT
    (SELECT LIMITE_PASES FROM USUARIOS WHERE ID = :usuarioId)            AS LIMITE,
    (SELECT COALESCE(SUM(PASES_PERMITIDOS), 0)
       FROM INVITADOS WHERE USUARIO_ID = :usuarioId)                     AS USADOS
FROM DUAL;

COALESCE devuelve 0 cuando la suma es NULL (o sea, cuando todavía no hay invitados). Sin él, el NULL se colaría por todas partes y las comparaciones fallarían.

4. El archivo de conexión: lib/oracle.ts

Es exactamente el mismo archivo en los dos proyectos. Se guarda en lib/oracle.ts (la carpeta lib es convención para código de servidor que no es un componente).

//lib/oracle.ts
import oracledb from "oracledb";

//En TypeScript, esto le dice al compilador que vamos a colgar
//nuestro pool de la variable global para que sobreviva los recargas de Next
declare global {
    var __oraclePool: oracledb.Pool | undefined;
}

export async function getPool(): Promise<oracledb.Pool> {
    if (!globalThis.__oraclePool) {
        globalThis.__oraclePool = await oracledb.createPool({
            user: process.env.ORACLE_USER,
            password: process.env.ORACLE_PASSWORD,
            connectString: process.env.ORACLE_CONNECT_STRING,

            //Nivel Free: no hace falta más
            poolMin: 1,
            poolMax: 4,
            poolIncrement: 1,
            poolTimeout: 60,
        });
    }

    return globalThis.__oraclePool;
}
ParámetroPor qué
poolMin: 1Mantiene una conexión abierta. En el nivel Free, la primera conexión tarda; tener una lista evita ese salto
poolMax: 4Una boda no necesita más. El nivel Free tiene un límite de sesiones y conviene no acercarse
poolTimeout: 60Si se agotan las conexiones, espera hasta 60 s antes de fallar
globalThis.__oraclePoolSobrevive a los recargas en desarrollo y evita pools duplicados
Este archivo nunca se importa desde un componente de cliente. Si un "use client" importa lib/oracle.ts, el navegador intentaría descargar oracledb y fallaría. Solo lo importan server actions y páginas de servidor.

6. La server action: validar, contar, guardar

Una server action es una función que corre en el servidor pero se llama desde el navegador como si fuera local. Next le pone el transporte, la serialización y la protección contra CSRF.

//app/actions/rsvp.ts
"use server";

import oracledb from "oracledb";
import { getPool } from "@/lib/oracle";
import { enviarConfirmacion } from "@/lib/email";

export type RsvpState = {
    ok: boolean;
    message: string;
};

export async function confirmarAsistencia(
    _prev: RsvpState,
    formData: FormData,
): Promise<RsvpState> {
    //1. Leer y limpiar
    const nombre = String(formData.get("nombre") ?? "").trim();
    const email = String(formData.get("email") ?? "").trim().toLowerCase();
    const asisten = Number(formData.get("asisten"));
    const restricciones = String(formData.get("restricciones") ?? "").trim();

    //2. Validar (la del navegador es cortesía; esta es la que vale)
    if (nombre.length < 3) {
        return { ok: false, message: "Escribe tu nombre completo." };
    }
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
        return { ok: false, message: "Escribe un correo electrónico válido." };
    }
    if (!Number.isInteger(asisten) || asisten < 1 || asisten > 10) {
        return { ok: false, message: "El número de asistentes no es válido." };
    }

    const usuarioId = Number(process.env.NEXT_PUBLIC_USUARIO_ID ?? 1);

    try {
        const pool = await getPool();

        //3. El contador: cuántos pases ya están comprometidos
        const usadosResult = await pool.execute(
            `SELECT COALESCE(SUM(PASES_PERMITIDOS), 0) AS USADOS
             FROM INVITADOS WHERE USUARIO_ID = :usuarioId`,
            { usuarioId },
        );
        const usados = Number((usadosResult.rows?.[0] as unknown[])?.[0] ?? 0);

        //4. El límite del cliente
        const limiteResult = await pool.execute(
            `SELECT LIMITE_PASES FROM USUARIOS WHERE ID = :usuarioId`,
            { usuarioId },
        );
        const limite = Number((limiteResult.rows?.[0] as unknown[])?.[0] ?? 0);

        if (usados + asisten > limite) {
            return {
                ok: false,
                message: `Lo sentimos: sólo quedan ${limite - usados} ${limite - usados === 1 ? "pase" : "pases"}.`,
            };
        }

        //5. Guardar
        await pool.execute(
            `INSERT INTO INVITADOS (USUARIO_ID, NOMBRE, EMAIL, PASES_PERMITIDOS, RESTRICCIONES)
             VALUES (:usuarioId, :nombre, :email, :asisten, :restricciones)`,
            { usuarioId, nombre, email, asisten, restricciones },
            { autoCommit: true },
        );

        //6. Avisar al invitado (sin tumbar la petición si el correo falla)
        try {
            await enviarConfirmacion({ para: email, nombre, asisten });
        } catch (error) {
            console.error("No se pudo enviar el correo de confirmación", error);
        }

        return { ok: true, message: "Te llegará un correo con los detalles. ¡Nos vemos ahí!" };
    } catch (error) {
        console.error("Error al guardar el RSVP", error);
        return { ok: false, message: "No pudimos guardar tu confirmación. Intenta de nuevo." };
    }
}

6.1 El contador y el límite, paso a paso

1. invitados ya confirmados SELECT COALESCE(SUM(PASES_PERMITIDOS), 0) → USADOS = 47 2. tope del cliente SELECT LIMITE_PASES FROM USUARIOS → LIMITE = 100 3. comparar USADOS + asisten > LIMITE ? 47 + 5 = 52 <= 100 → se guarda 47 + 60 = 107 > 100 → se rechaza con un mensaje
Esto no es a prueba de concurrencia. Si dos invitados confirman al mismo tiempo y ambos ven 95/100, los dos pasarían y quedarían 105. Para una boda es aceptable. La forma rigurosa es un SELECT ... FOR UPDATE sobre la fila del usuario o una restricción única. Si algún día importa, se implementa.

6.2 Bind variables: la parte de seguridad

Nunca se concatena texto del usuario dentro del SQL. Se usan bind variables: el SQL lleva :nombre y los valores viajan aparte.

//❌ Mal: inyección SQL. Con nombre = "x'); DROP TABLE INVITADOS; --" se borra la tabla
await pool.execute(`INSERT INTO INVITADOS (NOMBRE) VALUES ('${nombre}')`);

//✅ Bien: el valor nunca se interpreta como SQL
await pool.execute("INSERT INTO INVITADOS (NOMBRE) VALUES (:nombre)", { nombre });

Además de la seguridad, los binds permiten que Oracle reutilice el plan de ejecución: es más rápido.

6.3 useActionState: el puente con el formulario

DevuelvePara qué
estadoEl resultado: { ok, message }
formActionSe pasa al action del <form>
pendientetrue mientras se ejecuta. Sirve para deshabilitar el botón y evitar dobles envíos

El primer argumento de la acción (_prev) es el estado anterior. Next lo rellena solo; por eso el nombre empieza con guion bajo (se recibe pero no se usa).

7. El correo de confirmación

El correo lo envía el servidor, nunca el navegador: si se hiciera desde el cliente, la clave de la API quedaría pública.

7.1 Resend (recomendado)

npm install resend
//lib/email.ts
import { Resend } from "resend";

const resend = new Resend(process.env.RESEND_API_KEY);

export async function enviarConfirmacion({
    para,
    nombre,
    asisten,
}: {
    para: string;
    nombre: string;
    asisten: number;
}) {
    await resend.emails.send({
        from: "Boda Sonia y David <no-reply@tudominio.com>",

        subject: "¡Tu asistencia está confirmada!",
        html: `
            <div style="font-family: Georgia, serif; color: #1a1817;">
                <h1 style="color: #5c3a21;">¡Gracias, ${nombre}!</h1>
                <p style="font-family: sans-serif; font-size: 15px;">
                    Recibimos tu confirmación para <strong>${asisten}
                    ${asisten === 1 ? "persona" : "personas"}</strong>.
                </p>
                <p style="font-family: sans-serif; font-size: 15px;">
                    Nos vemos el 28 de diciembre de 2026 en el Centro Cristiano Izcalli.
                </p>

}
El remitente debe ser un dominio verificado. Resend exige verificar tudominio.com (agregando registros DNS) antes de enviar. No puedes usar un correo Gmail. Si no tienes dominio, la alternativa es Nodemailer.

    await transporte.sendMail({
        from: `"Boda Sonia y David" <${process.env.SMTP_USER}>`,
        to: para,
        subject: "¡Tu asistencia está confirmada!",
        html: `<p>Gracias ${nombre}, recibimos ${asisten} ${asisten === 1 ? "confirmación" : "confirmaciones"}.</p>`,

}

7.3 Qué pasa si el correo falla

En la server action, el envío está envuelto en su propio try después del INSERT. Así, si Resend o Nodemailer falla, la confirmación ya está guardada y el invitado ve el "¡Gracias!" de todos modos. El fallo se registra en la consola del servidor.

Orden correcto: guardar primero, enviar después. Al revés, un fallo de correo dejaría al invitado sin confirmación a pesar de haberla hecho.

8.2 NextAuth.js (Auth.js) v5

Se configura en un archivo auth.ts en la raíz del proyecto. Como el login es con correo y contraseña, se usa el proveedor de credenciales.

//auth.ts
import NextAuth from "next-auth";
import Credentials from "next-auth/providers/credentials";
import bcrypt from "bcryptjs";
import { getPool } from "@/lib/oracle";

export const { handlers, auth, signIn, signOut } = NextAuth({
    //Necesario en Vercel: Auth.js tiene que saber que el host es de confianza
    trustHost: true,

    //Con credenciales no hay flujo OAuth, así que la sesión es un JWT
    session: { strategy: "jwt" },

    providers: [
        Credentials({
            credentials: {
                email: { label: "Correo", type: "email" },
                password: { label: "Contraseña", type: "password" },
            },

            async authorize(credentials) {
                const email = String(credentials?.email ?? "").trim().toLowerCase();
                const password = String(credentials?.password ?? "");

                if (!email || !password) return null;

                const pool = await getPool();
                const resultado = await pool.execute(
                    `SELECT ID, NOMBRE, EMAIL, PASSWORD_HASH, LIMITE_PASES
                     FROM USUARIOS WHERE LOWER(EMAIL) = :email`,
                    { email },
                );

                const fila = resultado.rows?.[0] as unknown[] | undefined;
                if (!fila) return null;

                const [id, nombre, correo, passwordHash, limitePases] = fila;
                const valida = await bcrypt.compare(password, String(passwordHash));

                if (!valida) return null;

                //Esto es lo que Auth.js guarda en el token
                return {
                    id: String(id),
                    name: String(nombre),
                    email: String(correo),
                    limitePases: Number(limitePases),
                };
            },
        }),
    ],

    callbacks: {
        //Copia datos del usuario al token JWT
        async jwt({ token, user }) {
            if (user) {
                token.uid = String(user.id);
                token.limitePases = (user as { limitePases?: number }).limitePases ?? 0;
            }
            return token;
        },
        //Y del token a la sesión que ve la página
        async session({ session, token }) {
            if (session.user) {
                (session.user as unknown as { id: string }).id = token.uid as string;
                (session.user as unknown as { limitePases: number }).limitePases =
                    token.limitePases as number;
            }
            return session;
        },
    },
});

8.5 Proteger el dashboard (sin middleware)

El middleware de Next corre en el Edge Runtime, un entorno limitado donde oracledb puede fallar. Para un dashboard, la forma más simple y segura es preguntar por la sesión **dentro de la página de servidor**:

//app/dashboard/page.tsx
import { auth } from "@/auth";
import { signOut } from "@/auth";
import { redirect } from "next/navigation";
import { getPool } from "@/lib/oracle";

export default async function DashboardPage() {
    const session = await auth();

    //Si no hay sesión, afuera
    if (!session?.user) {
        redirect("/login");
    }

    const usuarioId = (session.user as unknown as { id: string }).id;
    const pool = await getPool();

    //Los invitados, con el nombre de cada acompañante (si se guardó)
    const invitados = await pool.execute(
        `SELECT i.ID, i.NOMBRE, i.EMAIL, i.PASES_PERMITIDOS, i.RESTRICCIONES, i.CREADO_EN
         FROM INVITADOS i
         WHERE i.USUARIO_ID = :usuarioId
         ORDER BY i.CREADO_EN DESC`,
        { usuarioId },
    );

    //El resumen
    const resumen = await pool.execute(
        `SELECT COALESCE(SUM(PASES_PERMITIDOS), 0) AS USADOS,
                COUNT(*) AS CONFIRMACIONES
         FROM INVITADOS WHERE USUARIO_ID = :usuarioId`,
        { usuarioId },
    );

    const fila = resumen.rows?.[0] as unknown[] | undefined;
    const usados = Number(fila?.[0] ?? 0);
    const confirmaciones = Number(fila?.[1] ?? 0);
    const limite = (session.user as unknown as { limitePases: number }).limitePases;
    const disponibles = Math.max(limite - usados, 0);

    return (
        <main className="min-h-svh bg-cream px-6 py-12">
            <div className="mx-auto max-w-5xl">
                <div className="flex items-center justify-between gap-4">
                    <h1 className="font-serif text-3xl text-coffee">Invitados</h1>
                    <form action={async () => { "use server"; await signOut({ redirectTo: "/login" }); }}>
                        <button className="rounded-full border border-sand px-5 py-2 font-sans
                                          text-[11px] uppercase tracking-[0.2em] text-coffee
                                          transition-colors duration-300 hover:bg-sand/20">
                            Cerrar sesión
                        </button>
                    </form>
                </div>

                {/*Tarjetas de resumen */}
                <div className="mt-8 grid gap-4 sm:grid-cols-3">
                    <div className="rounded-2xl border border-sand/60 bg-white p-6">
                        <p className="font-sans text-[10px] uppercase tracking-[0.25em] text-terracotta">
                            Confirmaciones
                        </p>
                        <p className="mt-2 font-serif text-3xl text-coffee">{confirmaciones}</p>
                    </div>
                    <div className="rounded-2xl border border-sand/60 bg-white p-6">
                        <p className="font-sans text-[10px] uppercase tracking-[0.25em] text-terracotta">
                            Pases usados
                        </p>
                        <p className="mt-2 font-serif text-3xl text-coffee">{usados} / {limite}</p>
                    </div>
                    <div className="rounded-2xl border border-sand/60 bg-white p-6">
                        <p className="font-sans text-[10px] uppercase tracking-[0.25em] text-terracotta">
                            Pases disponibles
                        </p>
                        <p className="mt-2 font-serif text-3xl text-coffee">{disponibles}</p>
                    </div>
                </div>

                {/*La tabla */}
                <div className="mt-8 overflow-hidden rounded-2xl border border-sand/60 bg-white">
                    <table className="w-full font-sans text-sm text-ink">
                        <thead className="bg-sand/20 text-left">
                            <tr>
                                <th className="px-4 py-3">Nombre</th>
                                <th className="px-4 py-3">Correo</th>
                                <th className="px-4 py-3 text-center">Asisten</th>
                                <th className="px-4 py-3">Restricciones</th>
                            </tr>
                        </thead>
                        <tbody>
                            {(invitados.rows ?? []).map((fila, indice) => {
                                const [id, nombre, email, asisten, restricciones] = fila as unknown[];
                                return (
                                    <tr key={String(id)} className={indice % 2 === 0 ? "bg-white" : "bg-cream/50"}>
                                        <td className="px-4 py-3">{String(nombre)}</td>
                                        <td className="px-4 py-3">{String(email)}</td>
                                        <td className="px-4 py-3 text-center">{Number(asisten)}</td>
                                        <td className="px-4 py-3">{String(restricciones ?? "—")}</td>
                                    </tr>
                                );
                            })}
                        </tbody>
                    </table>
                </div>
            </div>
        </main>
    );
}

TanStack Table sirve cuando hay ordenamiento, filtros o paginación con miles de filas; shadcn/ui es útil si quieres componentes ya montados (botones, diálogos, paginación). 10.1 El campo trampa (honeypot)

Un input invisible para los humanos pero visible para los bots. Si se llena, se descarta la confirmación en silencio.

       className="hidden" aria-hidden="true" />
